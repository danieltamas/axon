# Post-Ship Audit — axon-bus M1–M5 (2026-09-30)

**Scope:** `main...job/axon-bus/m0` (commits 689d305, 846e52e, 0c416c3), `crates/axon-bus/src`, `crates/axon-bus/ui`, `crates/axon-bus/tests`.
**Auditors:** bug hunter · security hardener · test skeptic. All three are same-vendor (Claude), so this audit is not a substitute for the cross-vendor Codex review that preceded it.
**Stance:** 27 findings after dedup — 0 P0 · 10 P1 · 12 P2 · 5 P3.
**Headline:** Nothing blocks shipping. The biggest risk is that the budget/stop gate is only advisory against a hostile agent:
- the actor on every bus CLI verb is self-declared (SEC-1);
- `grant` has no authority check (SEC-2);
- the gate fails open under write-lock contention (BUG-3/SEC-3, found by two auditors).

Content capture also outlives `serve` (BUG-1/SEC-4, found by two auditors).

Finding IDs follow the auditors' own numbering. When two auditors found the same defect, both IDs are listed on one entry.

## P1 — high

### SEC-1 · The actor on every bus CLI verb is self-declared
- **Where:** `cli.rs:100-240`, `main.rs:147-304`, `route.rs:44-71`, `serve.rs:52-56`
- **Found by:** security hardener
- **Failure scenario:** A prompt-injected worker runs shell commands. It can:
  - run `axon-bus send --from orch --to sibling --kind redirect …`, which delivers a message framed as coming from the sibling's parent;
  - self-accept a link;
  - release another agent's claims;
  - run `budget set <own-root> 1000Mtok` at 79% spend, which lifts the ceiling and clears the `budget:` stops;
  - run `serve --content` to switch capture on for everyone.

  The gate never inspects any of these calls.
- **Solved criteria:**
  - [ ] A Claude PreToolUse Bash call running `axon-bus send|ask|reply|grant|link|accept|claim|release` with `--from`/`--agent` ≠ the resolved actor is denied.
  - [ ] `budget set` and `serve --content` run from inside a governed session are denied.
  - [ ] Regression tests cover a forged `--from`, a self-accept, and an agent raising its own root budget.
  - [ ] `cargo test --workspace` is green.
- **Fix direction:** Police the bus CLI in the PreToolUse gate, using `tool_input.command` and `session_id`. Reserve budget raises and capture changes for the human, via the dashboard token.

### SEC-2 · `grant` has no authority check
- **Where:** `route.rs:74-93`, used at `route.rs:112-120`
- **Found by:** security hardener
- **Failure scenario:** Worker W in tree A runs `grant --from W --to rootB --thread t --ttl 999h` and then sends to rootB. That breaks §3's "a send to anything else is rejected". The TTL is also unbounded, and `parse_ttl` can overflow.
- **Solved criteria:**
  - [ ] `grant` succeeds only when the granter is a common ancestor of both endpoints (or the human). Otherwise it exits 3.
  - [ ] The TTL is capped, and overflow is rejected.
  - [ ] A regression test shows a self-grant followed by a send exits 3.
  - [ ] Green.

### BUG-3 / SEC-3 · The budget gate fails open under write-lock contention
- **Where:** `hook.rs:218-219`, `hook.rs:59`, `gate.rs:93-104`, `usage.rs:39-67`, `store.rs:159`
- **Found by:** bug hunter + security hardener
- **Failure scenario:**
  1. PostToolUse reads and parses the transcript tail inside the IMMEDIATE write transaction. This is slow on a first ingest of a long session, on a child falling back to the main transcript, or after a cursor reset.
  2. A sibling's PreToolUse waits out `busy_timeout` (150 ms), gets SQLITE_BUSY, and `apply` errors.
  3. Only already-recorded stops have doorbells, so the call is allowed.

  The first 100% crossing and the ≥90% stale hold have no doorbell, so both are skipped.
- **Solved criteria:**
  - [ ] Transcript read and parse run before `write_tx`; only the INSERTs sit in the transaction.
  - [ ] Test: another connection holds the write lock for ~300 ms while a tree is at ≥100% but not yet stopped, and PreToolUse still denies.
  - [ ] The stale hold and the first crossing are mirrored into a doorbell/state file.
  - [ ] Green.

### BUG-1 / SEC-4 · Content capture outlives `serve`; retention only runs while `serve` or `replay` runs
- **Where:** `serve.rs:52-56`, `serve.rs:124-129`, `transcript.rs:194-203`, `transcript.rs:272`
- **Found by:** bug hunter + security hardener
- **Failure scenario:** `serve --content` runs once and is killed. `content_capture='1'` persists, so every later hook stores redacted assistant text and tool commands indefinitely, and nothing deletes rows older than 7 days. That breaks both halves of §7.
- **Solved criteria:**
  - [ ] Once `serve --content` exits, the next PostToolUse stores `text IS NULL` (capture is a lease that `serve` refreshes).
  - [ ] With no `serve` running, rows with `ts < now-7d` are deleted by a rate-limited hook-path expiry.
  - [ ] A regression test covers each.
  - [ ] Green.

### TEST-1 · No test for the gate failing closed when its DB query errors
- **Where:** `gate.rs:~50`
- **Failure scenario:** The m3 unreadable-DB tests fail at DB open and deny via the doorbell. They never reach `verdict()`, so reverting the closure to `?` or `unwrap_or(None)` stays green.
- **Solved criteria:**
  - [ ] The DB opens, but the gate query fails (e.g. the `messages` or `budgets` table is renamed). PreToolUse denies with "could not check stops and budgets" for all four harnesses.
  - [ ] There is a twin case for a `budget::check`-only error, and a healthy-DB control that allows.

### TEST-2 · Budget-stop clearing scoped to `budget:<scope>` is untested
- **Where:** `msg.rs:289-299`
- **Solved criteria:**
  - [ ] (a) Child-scope and root-scope stops: raising the child budget keeps the root's deny; raising the root budget then allows.
  - [ ] (b) A peer stop survives a budget raise.
  - [ ] (c) A Stop hook acks the peer stop, but the budget stop still denies. Assert via `messages.acked_at`.

### TEST-3 · A stop to a root registered under id ≠ session id is untested
- **Where:** `hook.rs` `registered_as`/`resolve`, `msg.rs` `doorbell_names`
- **Solved criteria:**
  - [ ] `register --id orch --session S`, then send a stop to `orch`. A PreToolUse with `session_id=S` is denied.
  - [ ] The same holds for a budget crossing on the `orch` tree.
  - [ ] No-hub variant: the `S` doorbell denies.
  - [ ] A Stop hook with `session_id=S` acks the stop and removes both doorbells.

### TEST-4 · The USD-only budget with an unpriced model is untested
- **Where:** `budget.rs:~233`
- **Solved criteria:**
  - [ ] A USD-only budget plus unpriced captured usage gives a deny whose reason contains "USD-only".
  - [ ] A priced-under-ceiling control allows.
  - [ ] A zero-usage control allows.

### TEST-5 · The doorbell lifecycle across commit is untested
- **Where:** `hook.rs` `apply()` tail, `msg.rs` `silence_doorbell`
- **Solved criteria:**
  - [ ] A Stop hook on a stopped child removes `doorbells/child.json`.
  - [ ] A failed commit leaves the doorbell in place.
  - [ ] A second pending budget stop keeps the doorbell.
  - [ ] A denial stands when the commit fails.

### TEST-6 · Per-file ingest cursor semantics are untested
- **Where:** `usage.rs:44-97`
- **Solved criteria:**
  - [ ] Re-ingest, and ingest after an append, count each turn once.
  - [ ] Two agents on one path keep independent cursors.
  - [ ] A file shrunk below the cursor is re-read from 0.
  - [ ] A partial trailing line is ingested exactly once after it completes.

## P2 — medium

### BUG-2 · The stale-usage gate measures turn time, not receipt time
- **Where:** `usage.rs:69-78`, `budget.rs:267-270`. The frozen contract is `acceptance_m3.rs:9-10` ("newest usage receipt").
- **Failure scenario:** After any tool call longer than 120 s, or on resuming a session idle for more than 2 min, the next PreToolUse sees stale usage. It sends a false sync, and at ≥90% it denies parallel calls.
- **Solved criteria:**
  - [ ] Staleness uses an ingest receipt time.
  - [ ] Test: ingest a turn whose transcript timestamp is 10 min old, then PreToolUse immediately gives no stale warning and no deny at 95%.
  - [ ] The m3 stale tests stay green.

### BUG-4 · Uninstall from a different binary path deletes the backup and leaves the hooks
- **Where:** `install.rs:349-411`
- **Failure scenario:** Install from `~/.cargo/bin`, then uninstall with a `target/release` build. The config is judged "edited", `unwire` matches nothing, and the backup is deleted. On reinstall, the hooks are doubled.
- **Solved criteria:**
  - [ ] Install with exe A, uninstall with exe B: the config is restored byte-identical, or uninstall exits non-zero with the backup kept.
  - [ ] Reinstall with B leaves exactly one entry per event.
- **Fix direction:** Match `axon-bus hook <harness> <event>` regardless of exe path.

### BUG-5 / SEC-10 · Budget ceilings are not validated
- **Where:** `cli.rs:231-232`, `budget.rs:33-44`, `budget.rs:190-199`
- **Failure scenario:** `--usd -1`, `--usd NaN`, `--usd 0`, `-5tok`, or an overflowing `…Mtok` silently disables the budget. The §6 form `3usd` is rejected.
- **Solved criteria:**
  - [ ] Each bad value exits 2, with a unit test per value.
  - [ ] `parse_tokens` uses `checked_mul`.
  - [ ] `--usd` accepts only finite values > 0.

### SEC-5 · `redact` misses common credential shapes; truncation runs before redaction
- **Where:** `transcript.rs:280-319`; truncation at `transcript.rs:62`
- **Failure scenario:** All of these are stored in plaintext with capture on:
  - Bearer JWTs;
  - `postgres://user:pass@…`;
  - `AWS_SECRET_ACCESS_KEY=…`;
  - `sk_test_`, `ghs_`/`ghu_`/`ghr_`, `npm_`, `hf_`, `xapp-`, `ya29.`.

  A 200-char cut can also leave a short `sk-` stub.
- **Solved criteria:**
  - [ ] Unit tests cover each shape plus `password=`/`secret=` assignments and URL userinfo.
  - [ ] Redaction runs before truncation.

### SEC-6 · A stop sent to a root does not reach its running subagents
- **Where:** `msg.rs:267-285`, `hook.rs:118-128`
- **Failure scenario:** The orchestrator is stopped while it waits on the Task tool, and its subagent keeps getting allowed. Budget stops fan out to members; peer and human stops do not.
- **Solved criteria:**
  - [ ] The spec states the intended behaviour.
  - [ ] If stops should propagate: `pending_stop` matches unacked stops addressed to any ancestor, and a test shows that stopping the root denies the child's next PreToolUse.

### SEC-7 · The dashboard token gives no protection against other local users
- **Where:** `serve.rs:193-196`, `serve.rs:101-109`
- **Failure scenario:** Another uid runs `curl 127.0.0.1:7433/`, reads the token from the page, then reads narratives and POSTs stops. Separately, the ready-file temp at a predictable `tmp-<pid>` path follows symlinks.
- **Solved criteria:**
  - [ ] Either the credential is owner-only (a URL fragment, or the 0600 file) and GET `/` does not contain it, or the docs scope `serve` to single-user hosts.
  - [ ] The temp file is opened with `O_EXCL|O_NOFOLLOW` and mode 0600.

### SEC-8 · `AXON_BUS_PARENT` is trusted for any registered id
- **Where:** `hook.rs:47`, `hook.rs:128`, `hook.rs:135`, `hook.rs:287-289`
- **Failure scenario:** `AXON_BUS_PARENT=victimRoot claude -p …` attaches that session's subagents to the victim's tree. Their spend drains the victim's budget, and they escape their own.
- **Solved criteria:**
  - [ ] A foreign parent is rejected, and the child's `root_id` is its own session.
  - [ ] A regression test covers this.

### TEST-7 · Live Claude narrative via the Stop/SubagentStop hooks is untested
- **Solved criteria:**
  - [ ] With content on, a real Stop hook whose `transcript_path` holds an assistant line gives a snapshot narrative row.
  - [ ] SubagentStop does not attribute main-thread rows to the child.
  - [ ] A hook with a bad `transcript_path` exits 0.

### TEST-8 · Capture-off hiding of earlier text, and retention, are untested
- **Solved criteria:**
  - [ ] Replay with `--content`, then restart `serve` without it: the snapshot has no marker text, and the row structure remains.
  - [ ] Rows older than 7 days are absent from the snapshot and deleted by `expire`.
  - [ ] A row just inside the window is kept.

### TEST-9 · Keeping user edits across install/uninstall is untested for all four harnesses
- **Solved criteria:** per harness:
  - [ ] Install, edit, reinstall: the edit survives and there is exactly one axon entry.
  - [ ] Uninstall: the edit is kept and the axon entries are gone.
  - [ ] Unedited configs still round-trip byte-exact.
  - [ ] A stale-backup case is covered.

### TEST-10 · The `audit` head hash is untested
- **Solved criteria:**
  - [ ] stdout has `head <64-hex>`, equal to the last event hash.
  - [ ] A different chain gives a different head.

### TEST-11 · The localhost Origin and self-send are untested
- **Solved criteria:**
  - [ ] POST with `Origin: http://localhost:<port>` and a valid token gives 201.
  - [ ] A wrong port gives 403.
  - [ ] `send --from a --to a` exits non-zero with no "panicked" in the output and no new row.
  - [ ] The UI-draft behaviour is either tested in a DOM test or declared manual-only.

## P3 — minor

### SEC-9 · Doorbell file names collide on case-insensitive filesystems
- **Where:** `doorbell.rs:14-26`
- **Failure scenario:** `Worker` and `worker` share one file, so one agent going idle clears the other's fallback.
- **Solved criteria:**
  - [ ] Doorbell names are always hashed (or case-folded with a hash suffix).
  - [ ] A test covers two ids that differ only in case.

### BUG-6 · Doorbells and stop rows pile up for closed members
- **Where:** `budget.rs:98-106`, `budget.rs:310-312`, `msg.rs:289-296`
- **Solved criteria:**
  - [ ] Closing a stopped agent removes its doorbell once no stop is pending, or tree stops skip closed members.
  - [ ] A test covers this.

### BUG-7 · A partial-path release does nothing and exits 0
- **Where:** `claims.rs:110-114`
- **Solved criteria:**
  - [ ] A release that matches no claim exits non-zero and writes no audit event.

### SEC-11 · Stale usage below 90% never denies
- **Failure scenario:** This conforms to §6, but an agent that breaks its own ingest can keep spending while its last known total stays under 90%.
- **Solved criteria:**
  - [ ] The owner decides whether sustained staleness (e.g. >10 min) denies regardless of the total. This is a spec decision, not a code task.

### TEST-12 · Redaction is covered only at unit level
- **Solved criteria:**
  - [ ] A replay line containing `KEY=sk-…` ends up `[redacted]` in the snapshot and in every DB text column, including reasoning and progress rows.

## Verified clean
- **Gate error branches:** all stop and budget errors deny (`gate.rs:48-53`), and a denial stands when the commit fails (`hook.rs:253-258`). A missing agent row also denies.
- **Doorbells:** they are rung on every stop insert and silenced only after the ack commits. Alias names cover a root registered under `--id`. An unreadable doorbell denies.
- **Stop semantics:** peer stops are acked at the end of the turn; budget stops are excluded from that ack; `clear_bus_stops` is scoped; `budget:` threads are reserved from user sends.
- **Audit chain:** the head read and append happen in one IMMEDIATE transaction. The hash is length-prefixed, and UPDATE/DELETE triggers block edits.
- **SQL:** all parameterized. The only `format!` interpolates a constant filter.
- **serve:**
  - Loopback bind, with a Host allowlist that blocks DNS rebinding.
  - Exact Origin plus a constant-time token on every non-GET request.
  - CSP is self only, with no inline script.
  - X-Frame-Options is DENY, nosniff is set, and there is no CORS.
  - GET and SSE have no side effects.
- **UI:** only `textContent` is used, never `innerHTML`. Classes and glyphs come from fixed maps.
- **Privacy:** opaque reasoning is never stored. Peer messages are framed as untrusted.
- **install:** POSIX quoting is sound, and TOML/JSON are written through serializers.
- **Dependencies:** all new deps are pinned in `Cargo.lock`.
- **Usage dedupe:** `UNIQUE(agent_id, source_key)` holds, and the cursor advances only to a newline.
- **M1–M4 acceptance coverage** was judged FULL for the promised behaviours. The M5 serve tests fail loudly when a port can't be bound; nothing skips silently.

## Operator decisions (2026-09-30)
- **SEC-1:** the gate polices the bus CLI. A forged `--from`/`--agent` is denied, and `budget set` and `serve --content` are human-only (denied from any governed session).
- **SEC-6:** a stop propagates to the addressee's whole subtree.
- **SEC-7:** `serve` is scoped to single-user hosts (documented), and the ready-file is hardened.
- **SEC-11:** §6 stays as is; this is an accepted residual risk.

## Fix round (2026-09-30, uncommitted at time of writing)
- **Fixed in code:**
  - **SEC-1:** new `cli_guard.rs`, called from the gate.
  - **SEC-2:** a grant must shortcut an existing relay route, on a thread the granter has messaged, with a 24 h TTL cap. The frozen M2 test requires self-grants inside a connected tree, so "common ancestor only" was not possible.
  - **BUG-3/SEC-3:**
    - A gate-only fallback runs on a WAL read when the write lock is busy, and any write it needs fails closed.
    - The transcript is read and parsed before the write lock is taken, and a concurrent ingest is skipped by a cursor check.
  - **BUG-1/SEC-4:** capture is a 30 s lease that `serve --content` renews, and hooks run expiry every hour.
  - **BUG-2:** staleness is measured from `usage.received_at`.
  - **BUG-4:** hooks are matched by `axon-bus hook <harness> <event>` whatever the binary path; `uninstall` is split into `uninstall.rs`.
  - **BUG-5/SEC-10:** budget ceilings are validated.
  - **SEC-5:** redaction uses regex patterns and runs before truncation.
  - **SEC-6:** stops hold the addressee's subtree, and its doorbells.
  - **SEC-7:** the ready-file is created with `create_new` and 0600, and the single-user scope is documented in §7.
  - **SEC-8:** `AXON_BUS_PARENT` is trusted only inside the hook's own session tree.
  - **SEC-9:** doorbell names are lowercase-plain, or `=`-prefixed hashes.
  - **BUG-6:** close acks all stops, and tree stops skip closed members.
  - **BUG-7:** releasing a path that isn't claimed exits non-zero.
- **Verified:**
  - `cargo test --workspace`, including the unsandboxed M5 serve tests: all green.
  - Clippy is clean, and `git diff --stat HEAD -- crates/axon-bus/tests` is empty.
  - Smoke scripts:
    - A config edited after install keeps the user's edits.
    - Installing with binary A and uninstalling with binary B restores the config byte-identical, with one hook per event.
    - A real PreToolUse hook denies a forged `--from` and `budget set`, and allows a send as oneself.
- **Open:** TEST-1..12. Each needs a test written from its solved criteria by a different vendor (CANON test independence). The only new tests are unit tests for the parser, redaction and ceilings.
- **Accepted:** SEC-11.
