## Findings

Counts: bugs P0 1, P1 0, P2 4, P3 10 (15 total). Test findings 9 (P1 1, P2 4, P3 4).

### BUG-1 (P0, VERIFIED): bare `axon` panics at startup
- src/server.rs:43 (`.route("/api/health", get(api_health))`) is merged with the axon-bus dashboard router, which also routes `GET /api/health` (crates/axon-bus/src/serve.rs:102).
- Scenario: `axon --no-open --no-hooks --port 17999` prints the Dashboard link, then panics: `axum-0.7.9/src/routing/path_router.rs:70:22: Overlapping method route. Handler for GET /api/health already exists`. The default product entry point cannot start.
- Why unguarded: the e2e and every test use `axon bus serve`; no test starts the root binary.
- Solved when: `axon --no-open --no-hooks --port N` stays up and `GET /api/health` returns 200; a test that spawns bare `axon` is green.
- Fix: keep one `/api/health` (drop or rename the usage_api one, or serve a merged handler); add the root-binary smoke test.

### BUG-2 (P2, PLAUSIBLE): outbox does not re-check the grant at transmit
- crates/axon-bus/src/fed/outbox.rs:64 (`due`), fed/shares.rs `change`.
- Scenario: A queues to B while B is offline, then A turns `outbound` off (revision bumps). On reconnect the outbox retry (<=10 s) can beat the share resend (~1-2 s poll); rows go out at the old revision and B accepts if it has not learned the change.
- Solved when: with `outbound` off or the share removed, no queued row is transmitted (assert on B's inbox and A's outbox state).
- Fix: in `due`, join the share and require `state='active' AND outbound AND remote_inbound`; otherwise cancel with an audited reason.

### BUG-3 (P2, PLAUSIBLE): revision bump silently kills queued messages
- fed/remote.rs:206 and :230 stamp `revision` at enqueue; fed/receive.rs:237 rejects `stale_revision`; fed/outbox.rs:134 (`judge`) treats it as terminal.
- Scenario: any bump by either owner (flag change, member change) while a message is queued makes delivery a deterministic terminal reject. The sending agent gets no notice (only 24h expiry sends a `sync`). Same silent loss for `bad_time` (clock skew > 120 s) and `unknown_session`.
- Solved when: a queued message survives one revision bump (re-stamped and delivered) or the sender is told it was rejected.
- Fix: re-stamp from the current share at send time; send a `sync` notice on any terminal reject.

### BUG-4 (P2, PLAUSIBLE): share update dropped when the receiver answers `unavailable`
- fed/shares/sync.rs:115: `handle.request(..).is_ok()` counts an `{"type":"error","reason":"unavailable"}` reply as success and stops retrying.
- Scenario: B's DB is busy at the moment of the update; A does not resend until the next reconnect. B keeps the old revision, so BUG-3 style rejects follow.
- Solved when: an error reply keeps the share dirty and is retried.
- Fix: check `reply["type"] != "error"` before clearing the pending flag.

### BUG-5 (P2, PLAUSIBLE): unchecked i64 subtraction on untrusted input
- fed/receive.rs:222: `msg.expires_at - msg.created_at`.
- Scenario: a paired peer sends `created_at` near i64::MIN. Debug builds panic (receiver answers `unavailable`, sender retries forever). Release wraps and can store a never-expiring message.
- Solved when: extreme timestamps get a clean `bad_time` reject in both profiles.
- Fix: `checked_sub` / `saturating_sub`, or range-check each field first.

### P3 bugs
- BUG-6 (PLAUSIBLE): outbox `due()` (outbox.rs:64) runs the expiry UPDATE, `audit_outcome` and `msg::from_bus` as autocommit statements; `append_event` says "call inside write_tx", so the events hash chain can fork under concurrency. Wrap in `write_tx`.
- BUG-7 (PLAUSIBLE): a retransmit after a lost ack can hit `recipient_full`, `unknown_share` or `expired` before dedup (receive.rs, step 9); the sender marks rejected a row the receiver holds. Move dedup before those checks.
- BUG-8 (PLAUSIBLE): `fed/shares.rs:260 close()` deletes undelivered inbound rows by `to_id` and peer, not by the message's share. Unsharing one repo can drop another share's messages for the same agent. Delete by share.
- BUG-9 (PLAUSIBLE): the audit rejection budget (10/min/peer) counts both `in` and `out` rows; outgoing rejects can lock out a peer. Count `in` only.
- BUG-10 (VERIFIED by reading): fed/envelope.rs:19 `body_ok` uses `char::is_control`, so U+2028/2029 and bidi controls pass (A12 frame-injection hardening gap); refs may start with `-`. Reject Unicode format/separator classes; require refs to start alphanumeric.
- BUG-11 (PLAUSIBLE): `store_message` uses the remote-chosen `thread` as the local thread id; it can collide with local threads. Namespace it (`peer:<id>/<thread>`).
- BUG-12 (VERIFIED by reading): backoff is `1000<<attempts.clamp(0,4)` capped at 10 s with no jitter (outbox.rs:183); spec says 1-60 s jittered. Raise the cap, add jitter.
- BUG-13 (PLAUSIBLE): outbox and discovery loops are sequential with a 10 s request timeout; one blackholed peer blocks all others up to ~20 s (head-of-line). Send per peer concurrently.
- BUG-14 (PLAUSIBLE): `resend_on_connect` resends removed shares on every connect forever; `dashboard_sessions`, `fed_inbox`, `fed_sessions` are never pruned. Prune.
- BUG-15 (VERIFIED by reading): settings error bodies return the anyhow chain (path leak, owner-only); the budgets PUT is a lock-free read-modify-write on `config.toml` with a fixed `config.toml.tmp` name, so concurrent PUTs lose updates. Use generic error text, a per-write unique tmp and a lock.

Known open items not re-reported: remote pause/remove notices ineffective on the receiver, no `resumed` notice, over-limit rejections not counted, `recipient_full`. Related and not worse: re-pair after a one-sided remove needs both sides to remove.

## Test skeptic

- TEST-1 (P1): no test starts the root `axon` binary (see BUG-1). Solved when a test spawns it and polls `/api/health`.
- TEST-2 (P2): rate limits unguarded (peer 10/s burst 20, recipient 2/s burst 5, `rate_limited` retry). The tests sleep 510 ms between sends to dodge them. Add a burst test per limit and a retry assertion.
- TEST-3 (P2): `remote_text_byte_cap` only asserts 0 < frames < 12 and each <= 16 KiB; a far smaller cap passes. Assert the exact packing.
- TEST-4 (P2): no test for stale_revision after a flag change with a queued row, grant re-check at transmit (BUG-2/3), or outbox expiry outside the sender-restart path.
- TEST-5 (P2): no test for the `messages` table rebuild on an old DB (the schema test only checks column existence). Add the migration test from the probe above.
- TEST-6 (P3): timing boundaries are bracketed too loosely: the confirm window brackets 590 s and 601 s (595 s passes), invite expiry within +-5 s; `created_at` 120000/120001 ms and 60 s discovery staleness unprobed.
- TEST-7 (P3): A21 only has observed-path coverage; no raw-QUIC malicious wire probe, no 8192/8193 frame boundary, no forged ack/answer (FED-COVERAGE.md lists these).
- TEST-8 (P3): kill-window and crash-mid-delivery cases are absent; dedup across restart is covered but not with a half-written inbox.
- TEST-9 (P3): clock-skew tests via AXON_TEST_NOW_OFFSET_MS are not combined with queued delivery (BUG-3 `bad_time`).

Fake-pass smells: sleep-to-dodge-rate-limit (TEST-2), loose range assertions (TEST-3, TEST-6), existence-only schema check (TEST-5). All 439 green tests coexist with a P0 launch crash.
