# Design Context

Source: `DESIGN.md` (users, goals), `ui/dist/index.html` (the shipped Axon reference page) and `docs/BUS-PLAN.md` §7 (the bus dashboard spec).

## Users
The primary user is a multi-harness power user running 3–10 parallel agent sessions (Claude Code, Codex, OpenCode, Hermes) across repos, on their own machine. They glance at the page to answer three questions:
- Who is working right now, and on what?
- Who is talking to whom?
- What is it costing?

They step in when an agent needs a stop, a redirect or an answer.

## Brand
Axon is local "neural telemetry": precise, calm and instrument-like, never a SaaS admin panel.
- **The data is the visual.** The agent tree and the messages moving along it are the hero; chrome stays quiet.
- **Colour.** A near-black, green-tinted ground with an emerald signal accent (`#34d399` / `#6ee7b7`) in dark mode. Light mode is a green-tinted paper with a deeper emerald.
- **Type.** Space Grotesk for prose; JetBrains Mono for identifiers, numbers and small uppercase letter-spaced labels. Both are named with system fallbacks and no remote fonts, because the product has zero egress.
- **Glyphs.** Each harness has an original mark with its own colour token. No vendor logos, no emoji, no italics.

## Constraints
- Vanilla JS modules with no build step, embedded in the binary.
- CSP is self-only: no inline scripts or style attributes. Dynamic values go through the CSSOM.
- Light and dark themes via tokens on `:root`.
- Budgets: first paint under 100 ms, SSE event to paint under 50 ms, smooth at 200 agents.
- `prefers-reduced-motion` respected.
